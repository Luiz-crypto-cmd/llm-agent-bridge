# Security Policy

## Supported Versions

Only the latest release on the default branch receives security fixes. Older
releases and forks are not actively maintained.

| Version | Supported          |
| ------- | ------------------ |
| 2.0.1   | :white_check_mark: |
| < 2.0.1 | :x:                |

## Reporting a Vulnerability

Please report vulnerabilities privately instead of opening a public issue.

Use GitHub's **Security → Advisories → Report a vulnerability** flow
(Private Vulnerability Reporting) on this repository, or email the security
maintainer below.

- Do **not** open a public issue or disclose details before a fix is released.
- Include a clear description, affected versions, and — where possible — a
  minimal reproduction or proof of concept.
- We aim to acknowledge the report within 5 business days.

## Coordinated Disclosure (CVD)

1. You report the issue privately.
2. We confirm, triage, and agree on a timeline with you.
3. We prepare and release a fix.
4. We publish a GitHub Security Advisory crediting the reporter (if desired).
